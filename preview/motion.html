Design System / Motion

Motion

Motion is a language, not a decoration. The right animation tells a user what happened, where their attention should go, and what's about to be possible. The wrong animation makes the product feel slow. Five durations, three easing curves, one rule: every motion serves a function.

Duration tokens

Five steps. Pick the slowest that still feels instant for the gesture.
--ps-duration-instant
75 ms
Hover color swaps, focus rings. Should feel instantaneous.
--ps-duration-fast
150 ms
Button press, tooltip fade, accordion toggle. Default for most micro-interactions.
--ps-duration-standard
250 ms
Modal/drawer in-and-out, tab change, panel expansion.
--ps-duration-slow
400 ms
Page transitions, full-card content swap. Used sparingly.
--ps-duration-emphasis
600 ms
Hero parallax, onboarding reveals, success celebrations. One per screen, max.

Easing curves

Three curves. Standard for most things; decelerate for entrances; accelerate for exits.
--ps-ease-standard
cubic-bezier(0.4, 0, 0.2, 1)
Default. Symmetric acceleration. Use for state changes that have no inherent direction (toggles, tabs, button presses).
--ps-ease-decelerate
cubic-bezier(0, 0, 0.2, 1)
Entrances. Starts fast, settles. Use for elements coming into view — drawer opens, toast appears, dropdown reveals.
--ps-ease-accelerate
cubic-bezier(0.4, 0, 1, 1)
Exits. Starts slow, accelerates out. Use for elements leaving view — drawer closes, toast dismisses.

Choreography

When multiple elements animate, sequence matters more than duration.

Scrim before dialog

Open a modal by fading the scrim in first, then bringing the dialog in over the top. Reverse on close.

scrimdialog

Container then contents

A drawer slides in first; its internal elements stagger by 30 ms thereafter so the user perceives the chrome before scanning content.

drawerrow 1row 2

Exit faster than entry

Closing always uses the shorter of the duration pair. The user has decided to dismiss — get out of their way.

in: 250 msout: 150 ms

One emphasis per screen

Hero animations, success celebrations, parallax — at most one of these per screen. Two competing emphases cancel each other.

hero only

Reduced motion

All motion respects prefers-reduced-motion. Substitutes carry the same information without movement.

Default

Drawer slides in from the right at 250 ms with decelerate easing.

Reduced

Drawer cross-fades into place at 75 ms. Same start and end states; no translate.

Default

Toast slides in from the bottom-right corner with a 250 ms decelerate.

Reduced

Toast fades in at 75 ms in its final position; auto-announces via aria-live.

Never use motion as the only signal of state change. Pair every animation with a label, focus shift, or screen-reader announcement.

Code · how to use

CSS variables from tokens.css. Same names work in tokens.ts for the React kit.
/* Drawer entrance */
.drawer {
  transform: translateX(100%);
  transition: transform var(--ps-duration-standard) var(--ps-ease-decelerate);
}
.drawer.is-open {
  transform: translateX(0);
}

/* Drawer exit — shorter, accelerate */
.drawer.is-closing {
  transition: transform var(--ps-duration-fast) var(--ps-ease-accelerate);
  transform: translateX(100%);
}

/* Reduced motion — global short-circuit */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 75ms !important;
    transition-duration: 75ms !important;
  }
  .drawer { transform: none; opacity: 0; }
  .drawer.is-open { opacity: 1; }
}

Do & Don't

Rules that prevent most motion bugs.

Do

  • Animate transform and opacity — they're GPU-cheap.
  • Use decelerate for entrances, accelerate for exits.
  • Make exit shorter than entry.
  • Stagger siblings by 30–50 ms when they enter together.
  • Test with prefers-reduced-motion: reduce on.

Don't

  • Animate width, height, left, top — they trigger layout on every frame.
  • Use motion as the only signal of a state change.
  • Stack more than one emphasis animation per screen.
  • Override --ps-duration-* tokens inline. If you need a one-off, propose a new token.
  • Animate scrolling. Let the browser handle it.
