Design System / Form Patterns

Form Patterns

How to compose Inputs, Selections, Date Pickers, and Buttons into coherent forms. Covers field grouping, validation timing, error summaries, multi-step flows, and save/cancel patterns.

Field grouping

Each field has a label, an input, and optional hint text. Required fields use an asterisk and a screen-reader-only "required" annotation.
Shown on order confirmations and shipping labels.

Validation timing

Validate on blur, not on every keystroke. Async checks (uniqueness, format) run after a 400 ms debounce. Submit-time validation surfaces a summary at the top of the form.
Enter a valid email (e.g. alex@partssource.com).
Strong password.

Error summary

When a user submits with multiple errors, summarize them at the top of the form with anchor links to each field. Screen readers announce the summary via aria-live="assertive".

Fix 2 fields before submitting:

  • Email — Enter a valid email.
  • Password — Must be at least 8 characters.

Save & cancel

Primary action on the right, secondary (Cancel) immediately to its left. Both anchored to a footer divider. Cancel never destroys data without a confirm dialog.

Patterns at a glance

Five rules that cover 80% of form design decisions.

One column by default

Two columns only when the fields are paired (city + state, first + last name).

Top labels, never placeholders

Placeholder text disappears on focus and breaks accessibility. Always use a visible <label>.

Mark required, not optional

Most fields should be required. Mark the few that aren't with "(optional)" after the label.

Group related fields

Use <fieldset> + <legend> for clusters that share a heading (Address, Billing).

Auto-focus on entry

The first empty required field gets focus on page load. Don't auto-focus inside modals that already have a heading.

Disable submit only when nothing is filled

Let users try to submit and see errors — don't lock the button while they're still typing.

Multi-step forms

Pair every multi-step flow with the Stepper component. Show progress at all times; let users navigate back without losing data.
  • Validate each step before allowing forward navigation.
  • Persist data to local storage after each step so a refresh doesn't lose progress.
  • Show a "Review" step before final submit; let users edit any prior step from there.
  • If the flow is > 4 steps, consider a sidebar layout (vertical Stepper).
  • End with a clear confirmation page, not just a toast.

Do & Don't

Do

  • Validate on blur, not on every keystroke.
  • Summarize errors at the top of the form on submit.
  • Anchor primary action to the right of the form.
  • Preserve form state across navigation.
  • Write error copy that tells the user how to fix.

Don't

  • Disable submit until the form is "complete".
  • Auto-submit on Enter inside multi-step flows.
  • Use red asterisks without an accompanying screen-reader-only "required" label.
  • Strip whitespace silently — show what you trimmed.
  • Use a single "Save" button for both create and update flows.
