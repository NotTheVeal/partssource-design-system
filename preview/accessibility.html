Design System / Accessibility

Accessibility

PartsSource builds for clinical environments — operating rooms, biomed shops, procurement offices. Every screen must be usable with a keyboard, a screen reader, and one good eye in a noisy hospital hallway. This is the policy. The rest of the system inherits from it.

Target & Promise

The bar every component must clear before it ships.
Standard WCAG 2.1 · AA

All public-facing surfaces. AAA where text contrast is cheap to achieve.

Keyboard 100% reachable

Every action available via Tab, arrow keys, Enter and Space. No mouse-only paths.

Touch target 44 × 44 px min

Per WCAG 2.5.5. Padding counts; visible button can be smaller.

Focus indicator 3 px ring · 3:1 contrast

Visible against any adjacent surface. Never outline: none without a replacement.

Focus indicator

One ring, applied everywhere a keyboard user can land.
Spec box-shadow: 0 0 0 3px rgba(176, 198, 211, 0.91);
3 px Blue-Gray ring at 91% opacity. Sits outside the element's border (no offset needed). Contrast against the surrounding canvas must be ≥ 3:1.

Components that use a different ring (e.g. error inputs use red, segmented controls inset 3 px) document the variant on their own page.

Screen reader patterns

Eight rules that cover 90% of accessibility bugs in this codebase.

Use real semantic HTML

<button>, <a>, <label>, <table>. Don't reinvent with <div onClick>.

Label icon-only controls

Every aria-label reads like a verb-phrase: "Close drawer", "Remove filter", not "Close".

Associate inputs & labels

Either wrap with <label> or link via htmlFor / id. Floating labels still need this.

Announce async

Use aria-live="polite" for status, "assertive" for errors. Never use role="alert" for content that already had its own focus.

Hide decoration

aria-hidden="true" on icons, dividers, spacers. Don't make the SR read every •.

Describe state

aria-expanded on disclosure triggers, aria-selected on tabs, aria-checked on switches.

Trap & restore

Modals / Drawers trap focus while open and restore to the trigger on close. The kit handles this for you.

Errors are descriptive

Link error message via aria-describedby. Tell the user what is wrong + how to fix.

Reduced motion

Animation is decoration, not function.

All motion in this system respects prefers-reduced-motion: reduce. When set, transitions drop to 0 ms and oscillating/parallax effects are disabled. Static substitutes (e.g. cross-fade instead of slide) carry the same information.

Never use motion as the only signal that something happened. Pair it with a label change, a focus shift, or an SR announcement. See Motion for the full token set.

Pre-merge checklist

Every PR touching UI runs this.
  • Page navigates fully with keyboard alone. Tab order matches visual order.
  • Every interactive element has a visible focus indicator (3 px PS Blue-Gray ring).
  • All text passes WCAG AA against its background (verify with the contrast matrix above).
  • Icon-only buttons have a meaningful aria-label.
  • Form inputs have associated <label> elements.
  • Errors are linked via aria-describedby and describe the fix, not just the failure.
  • Modals / drawers trap focus and restore to trigger on close.
  • Live regions used for async status (aria-live on toast container, table loading, etc.).
  • Tested with VoiceOver (macOS), NVDA (Windows), or screen-reader of choice.
  • prefers-reduced-motion respected — animations short-circuit to fades or no-ops.

Do & Don't

High-leverage rules.

Do

  • Use color and shape/icon to indicate state — never color alone.
  • Test with the keyboard first. Mouse is the easier path.
  • Write error copy that tells the user how to recover.
  • Increase touch target padding when the visible button shrinks.
  • Treat AAA as the default for text, AA as the floor for decoration.

Don't

  • Rely on hover to reveal essential info — keyboard users never see it.
  • Use outline: none without a replacement focus ring.
  • Set tabindex ≥ 1 — it breaks logical tab order across the page.
  • Wrap <button> inside <a> or vice-versa.
  • Use placeholder text as the only label — it disappears on focus.
