Design System / Error Pages

Error Pages

Full-page error states for the four scenarios users actually hit. Each follows the same shape — code or icon, title, recovery copy, primary + ghost CTAs — so users learn the pattern across products.

404 — Not Found

A page the user reached but no longer exists. Most common cause: stale link from email or bookmark.
404

We couldn't find that page

It may have moved or been deleted. Try going back to your dashboard, or search for the part or order you were looking for.

500 — Server Error

Something went wrong on our end. Always offer Retry, never expose stack traces.

Something broke on our end

Your data is safe. Our team has been notified. Try refreshing in a few seconds, or contact support if it keeps happening.

403 — Permission Denied

User is authenticated but lacks access. Direct them to who can grant it.

You don't have access to this page

Ask your facility admin to grant you the right role. If you think this is a mistake, contact support and reference your account email.

Network — Offline

No connection detected. Used for both client-side offline and timeout failures.

You're offline

Check your internet connection and try again. We'll automatically retry once you're back online.

Voice

Same shape, same tone — every error page.
  • Title — what happened, in the user's words. Not "Error 500".
  • Body — what to do next. Not "An error occurred."
  • Primary CTA — verb-first. "Try Again" / "Request Access" / "Go to Dashboard".
  • Ghost CTA — secondary path or escape hatch. Always optional.
  • Never expose error codes, stack traces, or internal terminology in the body copy.
  • If the user lost data, say so explicitly — and where to find it if it's recoverable.
