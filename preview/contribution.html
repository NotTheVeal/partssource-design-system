Design System / Contributing

Contributing

A design system is a product. It has owners, a roadmap, a definition of done, and customers who depend on its contracts. This is how new components, tokens, and patterns enter the system — and how they leave.

Maintainer

When to add a new component

The bar is high. Most needs are met by composition.
QuestionAnswer · Result
Can this be built by composing existing components (Button + Input + Card etc.)?Yes → Compose. Don't add to the system.
Does at least one other team need this within the next 6 months?No → Build in your app. Revisit if a second team asks.
Does it solve a real, recurring user problem (not a stylistic preference)?No → Use existing patterns. Propose only with usage data.
Can the API be stable in 6 months — or will it churn with every consumer?No → Incubate in a consumer app first. Promote later.
Are you willing to own the component (code review, bug triage, deprecations) for 12 months?No → Find a co-owner or shelve.

Naming conventions

Predictable names are the cheapest documentation.
CSS tokens --ps-{level}-{role}-{variant}

--ps-prim-blue-500, --ps-sem-bg-canvas, --ps-cmp-modal-width-md. Level is prim · sem · cmp.

React components PascalCase

Singular, descriptive, no prefixes: Button, Drawer, FilterChip. Reserve Ps prefix for collision-prone primitives only.

Variants variant="…"

Lowercase nouns describing role, not appearance: primary, tertiary, pill. Never blue or orange.

Sizes size="sm | md | lg"

Two-letter abbreviations. Default is always md. xl / xs only when the component genuinely has 5+ sizes.

States (force) state="…"

default · hover · focus · pressed · disabled · loading. Used in docs to render every state without faking interaction.

Files kebab-case.html · PascalCase.tsx

preview/filter.html, UI Kit/Button.tsx. Match the page or component name exactly.

Versioning · Semantic

All releases follow semver. Consumers pin to majors and review minors.
Major · X.0.0

Breaking

  • Renamed or removed prop
  • Removed component
  • Changed default behavior
  • Token renamed/removed
  • Markup structure shift
Minor · 1.X.0

Additive

  • New component
  • New variant/size on existing
  • New optional prop
  • New token (no rename)
  • Deprecation warning (not removal)
Patch · 1.2.X

Fixes

  • Bug fix that restores documented behavior
  • Visual fix matching Figma spec
  • Docs / typo / example
  • Performance with no API change
  • Dependency security bump

Definition of Done

A component isn't "done" until every box is ticked. Maintainers will check this list during review.
  • Figma source published with all variants, states, and prop overrides — instance-swappable.
  • React + TypeScript implementation in UI Kit/ with typed props.
  • All visual states implemented: default, hover, focus, pressed, disabled, loading (where applicable).
  • Force-state prop (state="…") supported for docs and screenshots.
  • Component renders correctly when wrapped in a 320 px-wide container (responsive floor).
  • Keyboard fully reachable; Tab order matches visual order; focus indicator present.
  • Color contrast verified against the accessibility matrix.
  • Documented on its own preview/*.html page with: intro, states, tokens, a11y, do/don't, snippet.
  • Listed in preview/index.html under the correct section.
  • Added to UI Kit/Showcase.tsx with a representative example.
  • Tokens used end-to-end — no hardcoded hex values in component CSS.
  • Changelog entry added with rationale + migration notes (if breaking).
  • At least one consumer team has stress-tested it in a real screen.

Deprecation policy

Components leave the system gracefully.

When a component is replaced or removed, it enters a deprecation window. During that window:

  • The component still works, unchanged.
  • Its docs page is marked with a ⚠ Deprecated banner pointing at the replacement.
  • The React component emits a console.warn() on first render (dev only).
  • Minimum window: two minor releases or 90 days, whichever is longer.
  • Removal happens in the next major release; the changelog includes a one-line migration recipe.

Example: the orange Pill button is deprecated for ADA reasons. Its docs show a red banner pointing at the Primary button. Removal is scheduled for v2.0.
