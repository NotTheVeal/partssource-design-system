Modals, Dialogs & Drawers

Overlays interrupt the page to focus the user on a single decision, task, or piece of content. PartsSource uses four overlay patterns: Modal (multi-step or list-heavy task, dismissable), Dialog (single confirm/destructive prompt), Drawer (side panel for edit / detail flows), and Bottom Sheet (mobile equivalent of a drawer). All share the same chrome — 5 px radius, 24/32 px padding, 30 px Source Sans Light title, 14 px supporting copy, scrim at rgba(0,0,0,.45).

Accessibility

Modals are interruptions — they must be obvious, keyboard-operable, and announce themselves clearly to assistive tech.

Roles & ARIA

Container is role="dialog" (or alertdialog for destructive confirms) with aria-modal="true". Title element gets aria-labelledby; subtitle gets aria-describedby.

Focus management

On open, move focus to the first actionable element inside the dialog — not the close button. On close, restore focus to the trigger that opened the modal. Trap Tab/Shift+Tab inside the dialog while open.

Keyboard

Esc always closes. Enter triggers the primary CTA when focus is in the dialog body. Pagination supports ← →. Bottom sheet supports swipe-down to dismiss; provide an equivalent close button for keyboard users.

Contrast

Title #373F41 on #FFF = 10.6:1. Subtitle #4A4A4A = 8.6:1. Primary CTA #005BA6 / #FFF = 7.4:1. All pass AAA for normal text.

Scroll containment

Lock body scroll when modal opens. The modal body itself is the only scrollable region. Drawer also locks page scroll; bottom sheet does not — the page can scroll behind it because content is glanceable.

Hit targets

Close button is 24×24 visual but 40×40 effective hit area on touch. Pager buttons are 28×28 visual / 40×40 effective. Never put two interactive elements closer than 8 px on touch surfaces.

Do & Don’t

The most common modal mistakes — and what to do instead.

Do

  • Use a modal when the user must finish or cancel before continuing.
  • Lead with a verb in the title — “Send nudge,” “Delete list” — not “Are you sure?”
  • Put the primary action on the right and label it with what it does (“Send Nudge”), not “OK”.
  • Match scrim color to overlay type: .45 for modals, .32 for drawers and sheets.
  • Allow Esc, scrim-click, and the close icon to all dismiss the modal.

Don’t

  • Stack modals. If a modal opens a modal, redesign the flow — use steps or a drawer.
  • Use a modal for marketing announcements or non-blocking info — that’s a Toast or Banner.
  • Use a modal for long forms — a Drawer keeps the user oriented in the page they came from.
  • Disable the close button to force a decision. Always give the user a way out (even if it’s “Cancel”).
  • Auto-dismiss a modal after a timer. Modals are user-driven; toasts are time-driven.

When to use what

Picking the right overlay is the most important decision — everything else follows from it.
Modal

Multi-row selection, batch action

User picks one or more items from a list, then commits an action. e.g. “Select orders to nudge,” “Choose facilities to add to list.”

Dialog

Single yes/no decision

Confirm destructive action, confirm submit, confirm leave-without-saving. No inputs, no choices beyond the two action buttons.

Drawer

Edit or inspect a single record

User edits a record while staying oriented in the list they came from. e.g. Edit asset, view PO detail, edit a saved list’s metadata.

Bottom sheet

Mobile contextual action

Mobile-only equivalent of a drawer for quick choices that don’t warrant taking over the whole screen. Always glanceable in <3 actions.

Toast (not here)

System feedback, non-blocking

The user did a thing and we’re telling them it worked. Goes in the Alerts & Toasts page — never use a modal for this.

Popover (not here)

Inline contextual help

Anchored to a trigger, dismisses on outside click. Lives in the Tooltips & Popovers page — not a modal.
