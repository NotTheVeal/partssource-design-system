Getting Started

The PartsSource Design System is a shared vocabulary of tokens, components, and patterns that ship across every PartsSource surface — Marketplace, Pro, Command Center, and internal tooling. This page is the front door. Start here.

How your design reaches code

The token pipeline, in plain language. You do not need to write code — most days you press one button in Figma.
1. You designin Figma
→
2. You pushToken Studio
→
3. It buildsGitHub
→
4. It shows upStorybook
What is all this?

We keep all our design choices in one place in Figma — colors, spaces, and text sizes. When you change one there, it can flow all the way to the code that runs our products. This saves time and stops mistakes.

The short version: you design in Figma, you push with a plugin called Token Studio, GitHub builds it for you, and it shows up in Storybook. Storybook is a web page where we can see every part we have built.

Words to know
TokenA saved value with a name. Like "brand blue" or "small space." You use the name, not the number.
Token StudioA plugin inside Figma. It is the bridge. It sends your design choices to the code.
GitHubWhere the code lives. It also builds and checks the work on its own.
ComponentA part we build once and use again. Like a button, a card, or a menu.
Pull request (PR)A "please add my change" note. It lets the work get checked before it goes live.
StorybookA web page that shows every part we have built, live and up to date.
How to start the pipeline from Token Studio

Do this when you changed a value in Figma, like a color or a space, and you want it in the code.

  1. Open your file in Figma.The one where you made the change.
  2. Open the plugin.Click the Plugins menu, then click Tokens Studio for Figma.
  3. Check it points to the right place.It should say NotTheVeal/react-ui-kit. The first-time setup box below shows how to check this.
  4. Click Push.The Push button sends your change out.
  5. Write a short note.Say what you changed, like "New brand blue." A few words is fine.
  6. Choose "branch and pull request."Do not push straight to main. A pull request lets the work get checked first.
  7. Click OK. You are done.GitHub takes over now. You do not touch the code.
That is the whole push. No code. No typing commands. The one button is Push. GitHub does the rest.
First-time setup: connect Token Studio to GitHub (full steps)

You do this one time. It has four small parts. Take them in order. After this, you only press Push.

Part 1 — Get a GitHub key

A key is like a password just for apps. You make it once.

  1. Go to GitHub and sign in.Open github.com.
  2. Open your settings.Click your picture in the top right, then click Settings.
  3. Open developer settings.Scroll to the very bottom of the left menu and click Developer settings.
  4. Pick classic tokens.Click Personal access tokens, then Tokens (classic).
  5. Make a new one.Click Generate new token, then Generate new token (classic).
  6. Name it and set a date.Name it Token Studio. Set expiration to 90 days or longer.
  7. Check one box only: repo.That single box is all you need. Leave the rest alone.
  8. Click Generate token, then copy it.It starts with ghp_. You cannot see it again, so keep it handy for the next part.
Careful: this key is a secret, like a password. Do not paste it in a chat or an email. You will only paste it into Token Studio in the next part.

Part 2 — Add GitHub to Token Studio

  1. Open the plugin in Figma.Plugins menu, then Tokens Studio for Figma.
  2. Open its settings.Click the gear icon at the bottom of the plugin.
  3. Add a sync provider.Find Sync providers, click Add new, and choose GitHub.
  4. Fill in the boxes (see the table below).
  5. Click Save.This stores the connection.
NameAnything you like, such as react-ui-kit.
Personal access tokenPaste the ghp_ key you copied in Part 1.
RepositoryNotTheVeal/react-ui-kit — type it exactly.
BranchA new name like tokens/studio-sync. Never main.
File pathtokens — this is the folder name, not one file.
Multi-fileTurn this ON. Our tokens live in several files inside the tokens folder.

Part 3 — Pull once to line things up

  1. Click Pull.This brings the current tokens from GitHub into the plugin.
  2. Check the token sets show up.On the left you should see: primitive, semantic, semantic.dark, component, legacy.
  3. Check the themes show up.You should see: Primitives, Light, Dark, Component.
If you see all of those, you are connected right. You never have to do Parts 1 to 3 again.

Part 4 — How you push from now on

  1. Change a value.Edit a color, space, or text size in a token set.
  2. Click Push.Write a short note about what you changed.
  3. Keep your branch, not main.This makes a pull request so the work gets checked first.
  4. Click Push to confirm.You are done. GitHub checks it and the pipeline runs.

If something goes wrong

"Bad credentials"Your key is wrong or expired. Make a new one in Part 1.
"Not found"Check the Repository spelling: NotTheVeal/react-ui-kit.
Sets look emptyFile path must be tokens with Multi-file ON. Fix it, then Pull again.
Push went to mainChange Branch to a new name so it opens a pull request, not a direct change.
How to make a new part (component) in Token Studio

Say you want to add a brand new part, like a "Tag" or a "Callout." Its colors, spacing, and text sizes need their own tokens first. This is the part people get stuck on, so follow it slowly. It is easier than it looks.

The trick to know first

Token Studio has no "new component" button. You cannot make one from nothing. Instead you copy a part that already exists, then rename it. That is the normal, correct way. Everyone does it this way.

Part A — make the tokens (in Token Studio)

  1. Open Token Studio in Figma.In Figma, open the Plugins menu and click Tokens Studio for Figma. A panel opens on the side.
  2. Click the "component" set.On the left of the panel is a list of token sets: primitive, semantic, component, and so on. Click component. Now you see the tokens for every existing part, grouped by name (like button, card, badge).
  3. Pick a part that looks close to yours.If your new part is a small pill, the badge group is a good start. If it is a box, start from card. It does not need to be perfect. You will change it next.
  4. Hover a token in that group, then click the three dots (⋯).A tiny menu appears on the right side of the token row. This is where the copy option lives.
  5. Click "Duplicate."A copy appears right below, with a name ending in "-copy." This copy is the seed of your new part.
  6. Rename the copy to your part's name.Click the name and change the first word to your new part. Keep the dots and the shape. Example: change badge.background to tag.background. Keep the pattern yourpart.piece.property.
  7. Duplicate and rename for each piece your part needs.Most parts need a few: tag.background, tag.text, tag.border, tag.radius, tag.padding. Duplicate one at a time, rename each.
  8. Set each value by picking a token, not typing a number.Click a token's value box. Start typing { and a list appears. Pick a semantic token, like {semantic.color.brand.primary} for the background. Never type a color like #005BA7. Always point at a token.
  9. Push it to GitHub.Click the Push button (an up arrow, near the top of the panel). Type a new branch name like tag-tokens — never main. Add a one-line message. Click Push. This opens a pull request for you.
The one rule: every value points at another token, never a raw number. A hand-typed color like #005BA7 will not update when the brand changes. A token name like {semantic.color.brand.primary} will.

Part B — what happens next (all automatic)

After you push, you are done. The push is the only manual step. The pipeline takes over on its own. You do not touch anything else, and you do not need to wait on a person.

  1. The pipeline builds the tokens.GitHub turns your new tokens into code (the --ps-... names) with no one lifting a finger.
  2. The checks run themselves.GitHub runs the safety checks automatically. Green means good.
  3. Storybook updates on its own.When the checks pass, your change is live in Storybook. No merge to do by hand, no developer needed.
Not sure which group to copy, or what to name a piece? That naming choice is the only judgment call. Ask me, or ask a teammate — send the part's name and a screenshot and that is enough to guide you.
If you see red

Red means a step stopped. This is normal sometimes. It is a safety net, not a big problem. Here is what to do.

  1. Do not panic.Nothing broke on the live site. The check caught it before that.
  2. Click the red step.It opens a page that says what went wrong.
  3. Read the last few red lines.They usually name the file or the value with the problem.
  4. Ask a developer, or ask me.Share the link to the red step. That is all we need to help fast.

Quick install — Web

Bring the system into any HTML page.

Drop these two stylesheets in your <head>. That's it — every --ps-* token and the Source Sans Pro family is now available.

<!-- Tokens: primitive · semantic · component -->
<link rel="stylesheet" href="/design-system/tokens.css">

<!-- Type, color helpers, base resets -->
<link rel="stylesheet" href="/design-system/colors_and_type.css">

<!-- Source Sans Pro (only if not already loaded) -->
<link rel="stylesheet"
  href="https://fonts.googleapis.com/css2?family=Source+Sans+Pro:wght@300;400;500;600;700&display=swap">

Your first component — in 5 minutes

Build a simple form that uses tokens, Input, and Button.
1

Pick a component

Open the component index. Every card links to a page with states, props, and tokens.

2

Copy the markup

Each component page has a "snippet" block. Paste it in — the result will already be using your tokens.

3

Wire state

Use controlled values for Inputs and Selections. The README in UI Kit/ documents prop conventions.

4

Test states

Force state="focus" or state="disabled" while you build. Real interactivity takes over once you remove it.

5

Check accessibility

Run through the Accessibility hub checklist before merging — keyboard, focus, contrast, screen reader.

6

Ship it

If you needed to add a new component or token, follow the Contribution guide.
