Include 1–2 action buttons (Secondary SM style: 32 px, 10px Source Sans Pro Medium, 4 px radius, neutral grey border). All buttons use the same neutral Secondary style regardless of alert variant.

Multi-line Support

Alerts auto-grow to fit content (min-height 40 px). Best practice: limit to 2 lines (~140 chars) to avoid obscuring main content.
Scheduled maintenance will occur on Saturday, May 3rd from 2:00 AM to 6:00 AM EST. Some features may be temporarily unavailable during this time.
Two-line alert with dismiss. Text wraps naturally; icon and close button stay top-aligned.

Toast Notifications

Transient popups that appear bottom-right, auto-dismiss after 3–5 seconds. Use for non-blocking feedback: "Item added", "Changes saved", "Upload complete". 56 px min-height, 8 px radius, elevated shadow.

Accessibility & Best Practices

WCAG compliance, ARIA roles, and implementation guidance for inclusive alert design.
  • Use proper ARIA roles: role="alert" for critical errors (interrupts screen reader), role="status" for confirmations (polite)
  • Live regions for toasts: Wrap toast container in aria-live="polite" so screen readers announce new toasts
  • Don't rely on color alone: Each variant pairs color with a distinct icon (✓ success, ⚠ warning, ⓘ info, ✗ fail) — meets WCAG 1.4.1
  • Dismiss buttons need labels: aria-label="Dismiss alert" — × glyph alone is not accessible
  • Auto-dismiss timing: Toasts should persist 5+ seconds, pause on hover/focus, and never auto-dismiss critical errors (WCAG 2.2.1)
  • Color contrast: All alert text meets WCAG AA (4.5:1) against its tinted background; icons meet 3:1 (WCAG 1.4.11)
  • Keyboard support: Action buttons and dismiss controls must be reachable via Tab; focus order should prioritize the alert when newly inserted
  • Touch targets: Dismiss × and action buttons must hit 44×44px minimum (WCAG 2.5.5) — pad the hit area beyond the visible glyph
