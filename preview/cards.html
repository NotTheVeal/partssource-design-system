Accessibility & Best Practices

WCAG compliance, keyboard support, and implementation guidance for inclusive card design.
  • Interactive cards need keyboard support: Make entire card focusable with tabindex="0" and trigger action on Enter/Space
  • Hover elevation matches focus: 0 4px 12px shadow on hover — keyboard focus must show identical elevation + 2px blue outline
  • Clickable area: Entire 317×220px Event Card surface is interactive (not just "View Details" link) for larger touch target
  • Icon circles need meaning: 46px icon circles (toolbox, wrench, calendar) are decorative — use aria-hidden="true"; card title conveys event type
  • Semantic structure: Use <h3> for card titles ("Service Event", "Equipment Failure") so screen readers navigate by headings
  • Button vs link: "View Details" is navigation (<a>) not action; "See Buying Options" is <button> for modal trigger
  • Status badges must include text: Color-coded pills (blue, orange, red) always pair color with label ("Not Shipped", "Urgent")
  • Contrast ratios: Grey 1 (#4A4A4A) on white meets 8.7:1; metadata Grey 2 (#777) meets 4.6:1 (AA for body text)
