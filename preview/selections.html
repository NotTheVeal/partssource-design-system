Design System / Selections

Selections

Checkboxes and Radio Buttons for form selections. Both use 24×24 inputs with 1.5px stroke. Minimum 44×44px touch target (including label) for mobile accessibility.

When to Use

Selection model guidance for choosing between checkboxes, radio buttons, and toggle switches.
Component Use When Selection Model
Checkbox Users can select zero, one, or multiple options from a list. Each option is independent. Multi-select
Radio Button Users must select exactly one option from mutually exclusive choices. Cannot be deselected once selected (unless form is reset). Single-select
Toggle Switch Immediate on/off action with instant feedback. Changes take effect immediately without a "Save" button. Binary (on/off)
⚠️ Common Mistakes:
  • Don't use checkboxes when only one selection is allowed → Use radio buttons
  • Don't use radio buttons when users need to select multiple items → Use checkboxes
  • If there are >5 radio options, consider using a dropdown instead
  • If users should be able to select zero options, use checkboxes or add "None" to radio groups

Accessibility & Best Practices

WCAG compliance, keyboard support, and implementation guidance for inclusive form design.
  • Minimum 44×44px touch target (WCAG 2.5.5) — make entire label + control clickable; 24×24 control with 10px padding each side hits target
  • Keyboard navigation: Tab moves focus between controls; Space toggles checkboxes; Arrow keys navigate within radio groups
  • Focus indicators: 0 0 10px PS Blue glow (50% opacity) + 2px offset = 3:1 contrast against white (WCAG 2.4.11)
  • Group with <fieldset> + <legend> — screen readers announce the group label before each option
  • Checkboxes = multi-select, radios = single-select — never use radios when users can pick multiple, or vice versa
  • Labels must be explicit: "Enable notifications" not "Notifications" — context-free labels confuse screen reader users
  • Vertical stacking preferred: 8px minimum gap between rows; horizontal layouts make scanning harder and increase tap errors
  • Default selections: Pre-check only when it matches 80%+ of user intent; incorrect defaults cause submission errors
