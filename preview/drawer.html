          subtitle="Create a content bundle to grant access to modules."
          onClose={onClose}
        />
        {/* form fields scroll here */}
      </DrawerContainer>

      {/* Sticky footer — primary CTA never hides below the fold */}

      </div>
    </Drawer>
  );
}

07 · Accessibility

The drawer is always modal — focus-trap, scroll-lock, Esc, and proper ARIA roles are built into the component, not optional knobs.

Roles & ARIA

Shell is role="dialog" with aria-modal="true". aria-hidden flips with the isOpen prop so screen readers ignore the panel when closed. Always pair the title in DrawerHeader with an aria-labelledby reference if you replace the default header.

Focus management

FocusTrap from focus-trap-react activates when isOpen is true. fallbackFocus is [data-drawer-dialog] when nothing else is focusable. allowOutsideClick lets the scrim dismiss. On close, focus returns to the trigger that opened it.

Keyboard

Esc always closes via the component's own useEffect keydown listener — independent of FocusTrap's escapeDeactivates:false. Tab/Shift+Tab cycle inside the drawer only. Enter submits forms in the body.

Contrast

Title #2B2B2B on #FFF = 12.6 : 1. Subtitle #4A4A4A = 8.6 : 1. Footer rule #DCDCDC separates the sticky region — the contrast is structural, not chromatic.

Scroll containment

useScrollLock(isOpen) freezes the body while open — non-negotiable, the drawer is always modal. Inside the drawer, only the DrawerContainer scrolls (pass h-full overflow-y-auto or flex-1 overflow-y-auto).

Hit targets

Close button is the standard Button ghost iconOnly — 36×36 visual with comfortable padding. AddEntityCard / RemoveEntityCard list rows are 56 px+ tall on touch. Mobile drawers fill the viewport so all targets stay full-width.

08 · Do & Don't

Drawer vs. modal vs. sheet — pick right. A drawer is for productive work that needs space; reach for a Modal for confirmations and a Sheet for read-while-working surfaces.

Do

  • Use a drawer for create/edit flows — bundles, assignments, assessments — where the user fills in a focused form.
  • Use a drawer for multi-step selection (modules → profiles → confirm). Keep the step pills sticky in the header area.
  • Lead with a verb in the title: “Create Bundle”, “Create Assignment” — never “Bundle Form”.
  • Let Esc, the scrim, and the close icon all dismiss.
  • Put long bodies behind a sticky footer (flex-1 overflow-y-auto + footer outside the container) — never hide the primary CTA below the fold.
  • Return focus to the trigger button when the drawer closes.

Don't

  • Use a drawer for a single yes/no decision — that's a Modal/Dialog.
  • Stack drawers. If a drawer opens another drawer, fold it into the existing wizard with one more step.
  • Reuse the drawer to display read-only detail content — use a Sheet (non-modal) so the user can reference page state.
  • Forget to reset wizard state on open — useEffect(() => { if (isOpen) reset() }, [isOpen, …]).
  • Hide errors below the scroll fold. Pin field-level errors inline; pin form-level errors above the footer.
  • Auto-dismiss after a timer. Drawers are user-driven.

09 · Mobile & Performance

The drawer has no separate mobile variant — it fills the viewport below the 500 px breakpoint and tightens padding (p-4 md:p-8). These are the considerations that still bite on phones.

Layout & sizing

One panel, always right-side. max-w-125 (500 px) caps width on desktop; w-full takes over below it. Body padding switches from p-8 (32 px) at md to p-4 (16 px) below. Don't introduce a bottom-sheet variant — if the content doesn't fit, redesign the body.

Touch targets

Minimum 44 × 44 pt on iOS, 48 dp on Android. The close button's Button ghost iconOnly already hits 36 px visual; pad to 44 on touch. Stack form fields with at least 16 px gap. AddEntityCard rows are 56 px+ tall by default.

Sticky footer

For wizards and selection drawers, use the flex-1 overflow-y-auto pattern on DrawerContainer so the footer pins to the bottom. Stack footer buttons full-width on mobile — primary on top. Don't let the body scroll behind a half-visible CTA.

Keyboard & safe area

When the soft keyboard appears, push the focused field into view — the drawer's own scroll region handles this when you focus an input. Respect env(safe-area-inset-bottom) on the sticky footer for notched phones.

Content density

The drawer is a focused surface — not a dashboard. Keep one column on phones; collapse optional fields under a disclosure. Don't try to fit a 6-column table in 500 px — use the Table section for ≤ 3 columns.

Performance

Animate transform + opacity only — the source's translate-x-0 / translate-x-full already does this. The query options (Create Assignment, Create Assessment) pass enabled: isOpen so data is only fetched when the drawer opens. Defer heavy lists until 300 ms after open if needed.
