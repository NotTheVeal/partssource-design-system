Design System / Tokens

Token Sheet

PartsSource design tokens follow a strict three-level architecture. Primitives hold raw values; semantic tokens describe intent and reference primitives; component tokens reference semantic tokens. Components never reach past the semantic layer — change a primitive once and the change cascades cleanly through both layers above it.

Primitive

The raw palette. Holds the only hex codes, px values, font family strings and durations in the system. Nothing references anything else.

--ps-prim-blue-500: #005BA6; --ps-prim-space-4: 16px;

Semantic

Describes intent. A semantic token says what something is for — text, surface, success, focus. References primitives only.

--ps-sem-fg-primary: var(--ps-prim-gray-800);

Component

Component-property contracts. Reads from semantic tokens only. The button doesn't know about #005BA6 — it asks for action-default.

--ps-cmp-button-primary-bg-default: var(--ps-sem-action-default);

Exports

The same tokens are shipped in three formats. tokens.css is the source of truth; the other two are regenerated from it.
CSS Variables
tokens.css
Source of truth. CSS custom properties with full primitive → semantic → component cascade, plus [data-theme="dark"] override.
JSON · Style Dictionary
tokens.json
Nested primitive / semantic / component tree. Cross-references emitted as {path.to.token} so a transform pipeline can resolve them.
SCSS
tokens.scss
$ps-* variables, sectioned by tier. Includes a @mixin ps-dark-theme for dark-mode overrides.
Audit
audit-report.html
Drift report. Scans every preview/*.html for raw hex values that bypass tokens. Headline stats + top-20 offenders + per-file collapsible breakdown.
Governance
TOKEN_AUDIT.md
Drift report — every hex literal in preview/*.html that bypasses tokens.css, ranked by frequency. Regenerate after any preview-page change.
Governance
TOKEN_RECONCILIATION.md
Diff against the canonical NotTheVeal/PS-Design-Library Token Studio source. Flags hex typos, naming differences, and JSON-vs-implementation contradictions.

Using the tokens

Drop tokens.css into any page. Always reach for the highest level that's appropriate.
✓ Do

Reach for component tokens when styling a known component. background: var(--ps-cmp-card-bg);

✓ Do

Use semantic tokens for one-off elements where no component fits. color: var(--ps-sem-fg-tertiary);

✗ Don't

Don't reach past semantic into primitives in component CSS. background: var(--ps-prim-blue-500); bypasses intent.

✗ Don't

Don't hard-code hex values, px sizes, or font names anywhere outside tokens.css. The primitive layer is the only place raw values live.
