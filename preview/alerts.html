Design System / Alerts

Alerts

Inline notification banners that communicate status, feedback, and important information to users. Three core variants (Success, Info, Fail) come directly from Figma; Warning and dismissible/actionable patterns follow design system best practices.

Core Alert Variants

Pulled directly from the Figma Success Alert, Fail Alert, and Info Alert frames. Warning variant follows brand palette.

Dismissible Alerts

Add a close button (18×18 × icon, 24 px hit area) on the right. Use for low-priority info that users can safely dismiss.
New features are now available. Check out the latest updates.
Info alert with dismiss. Close icon opacity 60%, 100% on hover.
Your preferences have been saved successfully.
Success confirmation with dismiss. Use after non-critical user actions.

Alerts with Actions

Include 1–2 action buttons (Secondary SM style: 32 px, 10px Source Sans Pro Medium, 4 px radius, neutral grey border). All buttons use the same neutral Secondary style regardless of alert variant.
Payment failed. Please update your billing information.
Error alert with single action. Button uses neutral Secondary SM style (grey border, PS Blue hover).
This action cannot be undone. Are you sure you want to continue?
Warning with two actions. Use sparingly — limit to 2 buttons max per alert.
A software update is available. Restart now or schedule for later.
Info with choice actions. Primary action (Restart) on the right.

Multi-line Support

Alerts auto-grow to fit content (min-height 40 px). Best practice: limit to 2 lines (~140 chars) to avoid obscuring main content.
Scheduled maintenance will occur on Saturday, May 3rd from 2:00 AM to 6:00 AM EST. Some features may be temporarily unavailable during this time.
Two-line alert with dismiss. Text wraps naturally; icon and close button stay top-aligned.

Toast Notifications

Transient popups that appear bottom-right, auto-dismiss after 3–5 seconds. Use for non-blocking feedback: "Item added", "Changes saved", "Upload complete". 56 px min-height, 8 px radius, elevated shadow.
Item added to cart
Success toast. In production, appears fixed bottom-right (24 px margin), slides in from right, max-width 420 px. Shadow: 0 4px 12px rgba(0,0,0,.15).
Your changes have been saved
Info toast. Use for confirmations and status updates. Auto-dismiss after 4–5 seconds or allow manual close.
Upload failed. Please try again.
Error toast. Use sparingly — for non-critical errors that don't block workflow. Critical errors should use inline alerts or modals instead.

Accessibility & Best Practices

WCAG compliance, ARIA roles, and implementation guidance for inclusive alert design.
  • Use proper ARIA roles: role="alert" for Fail alerts (interrupts), role="status" for Success/Info (polite)
  • Icons convey meaning beyond color: 24×24 Lucide icons (circle-check-big, info, alert-triangle, circle-x) with 2px stroke pair with color — meets WCAG 1.4.1
  • Dismiss × needs label: 18×18 icon at 60% opacity; add aria-label="Dismiss" — visual alone is insufficient
  • Toast auto-dismiss: 3-5 second persistence, pause on hover/focus; never auto-dismiss Fail toasts with critical errors (WCAG 2.2.1)
  • Contrast verified: Success green (#0E7C55 on #E2F5EE) = 5.2:1; Info blue (#005BA6 on #EFF9FE) = 7.1:1; Fail red (#E00000 on #FEF0F0) = 5.8:1
  • Action buttons: Secondary SM style (32px height, 87px min-width) — keyboard navigable, 44×44px touch target with surrounding padding
  • Multi-line alerts: Icon and × align top (not center) when text wraps beyond 40px min-height
  • Toast stacking: Bottom-right fixed position (24px margins), 12px vertical gap, z-index 9999 — announced via aria-live="polite" container
