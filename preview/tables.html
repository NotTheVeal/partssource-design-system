Design System / Tables

Tables

Tables present structured data — orders, parts, assets, approvals — in scannable rows with sortable columns and inline actions. PartsSource ships three flavours: page-level tables (Parts Quotes, Approvals, Orders — tabs above, legend below, no card chrome), widget tables (the dashboard TableView component — wrapped in a card, with view-mode toggle and segmented control), and card grids for visual-first browsing. All three share the same type, color, and density tokens.

Accessibility

Data tables are one of the hardest patterns to make screen-reader friendly. Get the semantics right and the rest follows.

Semantics

Use real <table>, <thead>, <tbody>, <th scope="col">. If implementing as CSS grid (like above), apply role="table", role="row", role="columnheader", role="cell" to preserve semantics for AT.

Sorting

Sortable columns set aria-sort="ascending" / "descending" / "none". The header button announces the new sort order when clicked (live region).

Selection

Checkbox column has aria-label="Select row". The header checkbox is labelled "Select all 48 rows". When some-but-not-all are selected, it shows indeterminate state and reports aria-checked="mixed".

Keyboard

Tab walks the column headers, then enters the body. Arrow keys move between cells once focus is inside. Space toggles row selection. Enter opens the row detail.

Contrast

Body text #2B2B2B on #FFF = 13.6:1. Status pills all meet AAA. Hover state #F4F8FB on white is decorative only — never rely on it to communicate state.

Tabular numerals

All numeric columns (Ref, PO, Order #, Price) use IBM Plex Mono with font-variant-numeric: tabular-nums so digits align vertically and the eye can scan a column for outliers.

Do & Don’t

Common pitfalls when building tables, and what to do instead.

Do

  • Right-align numeric columns; left-align text and identifiers.
  • Show only the columns the user can act on — push everything else into row detail.
  • Persist sort, filter, and page-size in the URL so deep links work.
  • Make whole rows clickable for the most common action (usually “view detail”), with hover state to telegraph it.
  • Show row count in the footer; users want to know “how much more is there?”

Don’t

  • Use color alone to communicate status — pair with a label (the Status pill does both).
  • Force horizontal scroll on mobile. Collapse to a card list at < 768 px instead.
  • Mix interactive elements in cell text — keep actions in the action column or row menu.
  • Truncate identifiers (PO, Ref) — they’re what users search by.
  • Use zebra stripes and hover bg — pick one. PartsSource uses hover, not zebra.
