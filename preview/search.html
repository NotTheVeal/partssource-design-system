Design System / Search Bar

Search Bar

Search appears on almost every PartsSource screen — but the bar adapts to the job. The Global Search in the top nav queries the catalog. SRP Search sits with Categories on the marketplace. Inline Search filters the contents of a card or list view (Asset Inventory, lists). Search-within trims long filter facets. And a Collapsed magnifier hides search on dense headers (My Lists detail). All five share one stroke + one orange submit color so the affordance reads as “search” everywhere it appears.

Global · Top Nav

The catalog search that lives in the top nav. 40 px tall, 4 px radius, #DCDCDC stroke, with a flush 48 px orange icon-button on the right edge. Placeholder reads Search Keyword or Item Number. Submits as a full-page search regardless of the active route.

Accessibility

Search is the keyboard-first surface — get the labels, roles, and shortcuts right.

Roles

Wrap each bar in role="search". The input gets type="search" and either a visible <label> or an aria-label ("Search the catalog", "Search this list"). Submit and clear buttons need their own aria-label.

Keyboard

/ jumps focus to global search from anywhere. ↓ ↑ walks the suggestions list. Enter submits the highlighted suggestion or the raw query. Esc closes the menu and clears focus.

Type-ahead semantics

Menu is role="listbox" with aria-controls tied to the input's id. Each suggestion is role="option". Input gets aria-activedescendant pointing at the currently-focused option.

Hit targets

The 32 px Global bar's submit button is 34 × 32 — under the 44 px minimum, mitigated by also clicking the search icon or hitting Enter from the field. SRP at 40 / 48 px clears the bar. Collapsed icon is 36 × 36 with a 4 px hover pad → effectively 44 × 44.

Focus visibility

Focus ring is 3 px rgba(0,91,166,.15) outside the brand-blue border — 3.4 : 1 against white, passing 1.4.11 non-text contrast. Never hide the ring on :focus-visible.

Result announcement

After a query lands, render the result count inside an aria-live="polite" region: "22,165 results for probe". Screen reader users get the count without re-focusing the page.

Do & Don't

Picking the right variant for the job prevents 90 % of search-bar problems.

Do

  • Use Global search for catalog queries that navigate to results — orange submit signals "go".
  • Use Inline search for in-place filtering of card or list contents — quiet glyph signals "narrow this".
  • Persist the query in the URL on SRP submit so back-button and deep links work.
  • Bold the matched substring in type-ahead suggestions, not the whole row.
  • Surface a result-count caption after submit ("22,165 results for probe").
  • Show an X clear button as soon as the input has a value, before the submit.

Don't

  • Put orange submit on Inline or Within search — it implies a page navigation that won't happen.
  • Use the placeholder as the only label — it disappears the moment a user starts typing.
  • Hide the Global search behind the collapsed icon on desktop — it's the primary nav action.
  • Auto-submit on every keystroke for SRP — debounce to 250 ms or require Enter.
  • Show suggestions before the user has typed 2 characters — recent queries are the exception.
  • Mix variant heights on the same surface — pick one and stick to it.

When to use what

Five patterns, five jobs. Pick by what the query does — navigates, filters, or trims — not by how wide your container is.
Global

Catalog query

Top-nav field for everywhere in the app. Submits as a full-page navigation to the SRP. Always present, always orange.

SRP

Refine results

Wider 40 px field on the marketplace SRP. Same orange submit; the difference is presence (always populated) and scale (next to category dropdown).

Inline

Filter a card

40 px field embedded in a card or list view. As-you-type narrowing; no submit affordance, no navigation.

Within

Trim a long facet

32 px field inside a filter rail facet of > 8 options. Glyph sits inside the stroke; no submit.

Collapsed

Crowded header

Lone magnifying glass next to a page title. Expands inline on click. Only when the header is genuinely out of room.
